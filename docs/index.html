Plugin QGIS // Mission Control FTTH

Controle aerien

ST-AIR inspecte vos livrables aeriens (poteaux, cables, boitiers, fiches d'appuis) en croisant shapefiles, Excel terrain et CSV GSPOT. Tout reste sur votre poste : pas de serveur, pas de compte, pas de telemetrie. Vous ouvrez QGIS, vous designez un dossier, vous cliquez demarrer.

01 // Modules d'analyse

5 controles, 1 rapport Excel consolide.

Chaque module examine une facette de votre livrable. Activez seulement ceux dont vous avez besoin : le rapport s'adapte a votre selection.

01

MAJ BD

Mise a jour poteaux

Prepare les modifications a appliquer au shapefile infra_pt_pot a partir de l'Excel FT-BT KO : etat, proprietaire, etiquettes.

infra_pt_pot FT-BT KO.xlsx MAJ_FT MAJ_BT
02

Verification CAP_FT

Appuis fibre vs fiches Orange

Croise les poteaux POT-FT avec les fiches d'appuis Orange. Detecte les absents, les hors-etude, les doublons et les ecarts de coordonnees.

etude_cap_ft FicheAppui_*.xlsx CAPFT_DETAIL CAPFT_RESUME
03

COMAC

Appuis BT, cables, boitiers

Capacites FO, portees PCM vs distance reelle, boitiers fibre optique, appariement spatial cable-appui. Module le plus complet.

etude_comac cables.shp bpe.shp COMAC_*
04

GESPOT vs C6

11 criteres croises

Compare les exports CSV GESPOT terrain aux declarations Excel C6 : hauteur, force, commune, proprietaire, etat, materiau, XY.

GSPOT/*.csv FTTH-*-ETUDE.xlsx GESPOT_C6
05

C6 vs BD

Cables gras C6 vs shapefile

Confronte les annexes C6 Orange (cables en gras uniquement, nouveaux a poser) au shapefile des poteaux.

infra_pt_pot FTTH-*.xlsx C6BD_ANALYSE
100 % local, zero telemetrie. ST-AIR lit les fichiers de votre dossier projet et ecrit le rapport a cote. Aucune connexion sortante n'est effectuee, aucun compte n'est requis, aucune donnee n'est envoyee en ligne.
02 // Architecture technique

La machinerie sous le capot.

Trois lectures d'une meme realite : le flux de donnees fichier-par-fichier, la topologie des modules en orbite autour du coeur, et la validation securite NFC 11201-A1 qui contraint COMAC. Aucune base de donnees, aucun serveur : tout passe par des fichiers locaux.

arch-flow.svg // 4 couches : sources -> coeur -> workflows -> modules
Sources ambre : fichiers Excel / shapefile obligatoires
Sources neutres : CSV / XML / fiddcpi optionnels
Lien en pointille : lecture conditionnelle selon module actif
Different de la version Orange / Axione. Dans l'architecture Orange, les sources incluaient PostgreSQL (schema COMAC + fddcpiax) et un Mode Projet avec db_layer_loader. Ici tout passe par des fichiers locaux : le plugin ne cherche jamais de connexion SQL, ne charge pas de layers PG, et ecrit le rapport directement dans le dossier projet. C'est strictement la meme logique metier, sans dependance serveur.
arch-constellation.svg // Core + 5 workflows + 5 modules metier + services transversaux
Modules metier (orbit externe)
Workflows (orbit interne)
Services transversaux
Sortie : rapport Excel consolide
5 modules, 5 workflows, 1 coeur. Chaque workflow est le pilote d'un module metier : il prepare les donnees, execute le controle, et retourne les resultats au `BatchOrchestrator` qui les agrege dans le rapport unique. Les services transversaux (parsers, readers, security_rules) sont partages : changer une regle NFC dans `security_rules.py` impacte tous les modules concernes en un seul endroit.
arch-security.svg // Validation portees max cables FO aeriens (NFC 11201-A1)
Entree / extraction
Validation securite (coeur NFC)
Export rapport
Pipeline transitoire
Pour le vent, c'est le meme module qu'avant. Les portees maximales NFC 11201-A1 et les codes PRYSMIAN sont integres directement dans `security_rules.py` (catalogue statique). Aucun appel reseau, aucune BDD : le plugin connait les regles a l'avance et les applique hors-ligne. Seules les donnees du Excel COMAC changent d'un projet a l'autre.
03 // Sequence d'execution

Un workflow, 5 etapes, 0 ambiguite.

Le meme enchainement quel que soit le projet. L'interface vous guide, le plugin bloque tant que les prerequis ne sont pas remplis.

01
T + 0s

Ouverture du plugin

Icone ST-AIR dans la barre d'outils QGIS. La fenetre apparait, le champ SRO affiche "En attente du dossier projet".

02
T + 10s

Selection du dossier

Dossier nomme selon le SRO avec tirets : 63041-B1I-PMZ-00003. Le plugin le convertit automatiquement en SRO 63041/B1I/PMZ/00003 et scanne les sous-dossiers CAP FT, COMAC, GSPOT.

03
T + 20s

Confirmation & modules

Les couches QGIS (infra_pt_pot, etude_cap_ft, etude_comac) sont detectees automatiquement dans le projet. Vous cochez les modules pertinents, le bouton Demarrer se debloque quand tout est vert.

04
T + 2-8min

Execution asynchrone

Les modules tournent en arriere-plan QGIS. Barre de progression par module, journal detaille en direct. Vous pouvez continuer a travailler dans QGIS pendant l'execution.

05
Livrable

Rapport Excel consolide

Un seul fichier rapport_<SRO>_<date>.xlsx ecrit dans le dossier projet. Feuille de garde "TABLEAU DE BORD", puis une feuille par module, codes couleur uniformes OK / Avertissement / KO.

04 // Dossier projet

Structure attendue du dossier.

Respectez la convention de nommage du dossier racine et placez les fichiers aux emplacements ci-dessous. Le plugin se charge de detecter les sous-dossiers.

~/projets/63041-B1I-PMZ-00003
63041-B1I-PMZ-00003/ # SRO : slashes -> tirets |-- BASE DE DONNEES/ | |-- NGE/ # shapefiles EPSG:2154 (Lambert-93) | | |-- infra_pt_pot.shp (+ .dbf .shx .prj .cpg) | | |-- etude_cap_ft.shp | | |-- etude_comac.shp | | |-- cables.shp | | |-- bpe.shp | | |-- za_nro.shp | |-- GSPOT/ # CSV UTF-8 BOM, separateur ; | | |-- 20260403_GESPOT_63041.csv |-- CAP FT/ # fiches d'appuis Orange | |-- CMD 1/ | | |-- FicheAppui_0747699.xlsx | | |-- FTTH-xxx-ETUDE-...xlsx # annexe C6 (optionnel) |-- COMAC/ | |-- NGE-B1L-00003-PA-1_ExportComac.xlsx | |-- PCM/ # calculs PCM (optionnel) | |-- *.xml |-- FT-BT KO B1L_00003.xlsx # recap MAJ (optionnel) |-- rapport_63041_B1I_PMZ_00003_<date>.xlsx # genere par ST-AIR
Module Shapefiles requis Fichiers Excel / CSV
MAJ BD infra_pt_pot FT-BT KO *.xlsx
CAP_FT infra_pt_pot, etude_cap_ft CAP FT/**/FicheAppui_*.xlsx
COMAC infra_pt_pot, etude_comac, cables, bpe COMAC/*ExportComac*.xlsx + PCM XML (opt.)
GESPOT vs C6 - GSPOT/*.csv + annexes C6
C6 vs BD infra_pt_pot FTTH-*-ETUDE-*.xlsx
Attention troncature DBF. Le format shapefile coupe les noms de champs a 10 caracteres : commentaire devient commentair, etiquette_jaune devient etiquette_. ST-AIR reconnait automatiquement les deux variantes (nom long et nom tronque), vous n'avez rien a changer.
05 // Livrable final

Le rapport Excel, anatomie complete.

Un seul fichier, une feuille par module, des codes couleur stricts. Ouvrable dans Excel, LibreOffice, ou tout tableur moderne.

Feuilles produites

TABLEAU DE BORD
KPI par module, camemberts OK/KO, liens directs vers les feuilles detaillees.
MAJ_FT / MAJ_BT
Modifications a appliquer, ligne par ligne : gid, champ, ancienne valeur, nouvelle.
CAPFT_DETAIL
Statut par appui FT : OK, ABSENT QGIS, HORS ETUDE, DOUBLON.
CAPFT_RESUME
Synthese chiffree CAP_FT : totaux par statut, taux de conformite.
COMAC_DETAIL
Ligne par appui BT : boitier, cables, capacites, portees, statut global.
COMAC_CABLES
Anomalies cables : ecart capacite, cable declare absent, cable present non declare.
COMAC_PORTEES
Portee PCM (XML) vs distance geometrique reelle (shapefile cable).
GESPOT_C6
11 criteres croises GSPOT / C6, OK ou KO par appui avec valeur attendue / valeur trouvee.
C6BD_ANALYSE
Cables en gras des annexes C6 vs shapefile. Detection des ecarts topologiques.
GLOSSAIRE
21 termes metier expliques : SRO, CAP_FT, COMAC, C6, BPE, PMZ, NRO, PM, portee, etc.
DICTIONNAIRE
Structure ISO/IEC 11179 : nom, type, longueur, description, exemple, par champ.
COMAC_DESSIN_XX
Optionnel. Schemas polaires haute definition, un par appui COMAC verifie.

Codes couleur uniformes

OK - Conforme

Aucune anomalie detectee. Aucune action requise.

Avertissement

Anomalie mineure a verifier. Non bloquant pour la livraison.

KO - Non conforme

Anomalie a corriger obligatoirement avant livraison au donneur d'ordre.

07 // Foire aux questions

Les reponses rapides.

Pour le detail, voir le guide sous-traitant complet. Sinon contactez votre chef de projet.

Installation

Quelle version de QGIS est requise ?

+
QGIS 3.28 LTR au minimum. Le plugin est compatible jusqu'a QGIS 4.x (PyQt6). Pour la stabilite en production, la version 3.44 LTR est recommandee.

Le plugin a-t-il besoin d'une connexion internet ?

+
Non. ST-AIR fonctionne 100% en local. Il lit les fichiers de votre dossier projet et ecrit le rapport a cote. Aucune API externe, aucune telemetrie, aucun compte utilisateur.

Le plugin fonctionne-t-il sous macOS et Linux ?

+
Oui. QGIS et ST-AIR sont multiplateformes. Les procedures sont identiques sur Windows, macOS et Linux ; seuls les chemins diffèrent.
Dossier projet

Quelles couches QGIS dois-je charger ?

+
Selon les modules actives :
  • infra_pt_pot : obligatoire pour MAJ BD, CAP_FT, COMAC, C6 vs BD.
  • etude_cap_ft : obligatoire pour CAP_FT.
  • etude_comac, cables, bpe : obligatoires pour COMAC.
Les noms doivent etre exactement ceux-ci (ST-AIR cherche par nom de couche).

Pourquoi les noms de champs sont differents entre shapefile et rapport ?

+
Le format DBF limite les noms de champs a 10 caracteres. Donc commentaire devient commentair, etiquette_jaune devient etiquette_. ST-AIR reconnait automatiquement les deux variantes.

Puis-je renommer les shapefiles ?

+
Non. ST-AIR attend des noms de couche precis (infra_pt_pot, etude_cap_ft, etc.). Vous pouvez en revanche placer les fichiers dans n'importe quel sous-dossier.
Anomalies

Un appui apparait "ABSENT QGIS", que faire ?

+
L'appui est declare dans un Excel terrain mais introuvable dans le shapefile. Verifiez :
  • Le numero exact (prefixe E, suffixe /commune).
  • Que le shapefile est a jour (re-import si necessaire).
  • Faute de frappe dans l'Excel.

Que signifie "HORS ETUDE" ?

+
L'appui existe dans le shapefile mais sa position tombe en dehors de tous les polygones de la couche etude_*. Agrandissez le polygone ou verifiez que l'appui doit bien etre inclus.

Erreur "CRS incoherent" au lancement

+
Une couche est dans un autre systeme de coordonnees que EPSG:2154 (Lambert-93). Menu Vecteur -> Outils de gestion de donnees -> Reprojeter une couche, choisissez EPSG:2154, sauvez puis relancez.
Rapport & support

Mon livrable est-il modifie par ST-AIR ?

+
Non. Le plugin est en lecture seule sur vos fichiers source. La seule ecriture se fait dans le rapport Excel, qui est un nouveau fichier dans le dossier projet.

L'option "Schema poteau COMAC" ralentit beaucoup, pourquoi ?

+
Elle genere une image haute definition par appui (typiquement plusieurs centaines). Activez-la seulement si vous avez besoin du controle visuel. Sur 700 appuis, l'option peut ajouter 3 a 5 minutes a l'execution.

Qui contacter en cas de probleme ?

+
Question metier (que declarer ? quel format ?) : votre chef de projet / donneur d'ordre.

Question technique (bug, erreur bloquante) : transmettez par email :
  • La capture du message d'erreur.
  • Un extrait du Journal des messages QGIS, onglet ST-AIR.
  • La version QGIS (Aide -> A propos) et la version plugin (Extensions -> Installees).
Objet suggere : [ST-AIR] <SRO> - <resume>.
